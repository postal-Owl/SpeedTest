Это небольшая библиотека для замера времени произвольного кол-ва лямбда выражений (функций).
Состоит на данный момент (v1.1) из пары функций + функция печати STPrint()
При чем из-за того что эти функции шаблонные, практически вся реализация находится в заголовочном .h файле.

    SpeedTest():
Реализованная функция принимает на вход лямбда-выражения
и считает время выполнения переданной лямбда-функции.
Замер времени производится N раз.
N - первый параметр функции.
После всех итераций считается среднее арифметическое и возвращается в виде vector<double>.

Пример использования:
У нас есть некоторая произвольная функция с произвольным кол-вом параметров foo(...) {...} (это может быть и метод и конструктор класса и что угодно).

int main()
{
    ...
    SpeedTest(100,                // Кол-во повторных вызовов каждой лямбда функции
        [] { MyClass x; },            // Лямбда функция - внутри может быть что угодно
        [] { foo(1, 2, 3.14); },      // Например, вызов функции
        [] { ... });
    ...
}



    SpeedTestSub():
Аналогичная функция, но с важным отличием! 
Второй параметр (первое лямбда-выражение, переданное в функцию) используется для вычитания из последующих замеров.
Это можно использовать в ситуациях, когда есть общая часть во всех лямбда выражениях, время которой не хотелось бы учитывать.
Пример:
Предположим мы написали свою функцию быстрой сортировки и захотели проверить ее со встроенной функцией sort() из библиотеки <algorithm>.
Для начала создадим контейнер/массив, который мы будем сортировать, и заполним его произвольными значениями.
Делать это заранее - не вариант, т.к. при передачи массива в лямбда функцию по ссылке массив просто отсортируется на первой итерации и дальше алгоритм будет получать на вход отсортированный массив.
Передавать копию тоже не вариант, т.к. компилятор ругается мол нельзя менять значения в массиве.
Остается вариант - создавать на каждой итерации новый контейнер/массив, заполнять его и уже после этого вызывать алгоритм сортировки для нового массива данных.
Но проблема в том, что нас же интересует исключительно время работы алгоритма сортировки (в данном случае), 
и не итересует сколько времени тратиться на выделение памяти и заполнение массива, 
но при этом в результате будет учитываться время на заполнение массива.

В такой ситуации я посчитал так: "Почему бы не выделить общую часть для всех лямбда функций, которая меня не интересует при замерах времени, и просто вычитать это время из результата?".
Собственно так я и сделал.
Вот как это выглядит:

SpeedTestSub(10,
        [] { std::vector<double> Array;
            for (int i = 0; i < 1e6; i++)
                Array.push_back(rand()); },
        [] { std::vector<double> ArrayQS;
            for (int i = 0; i < 1e6; i++)
                ArrayQS.push_back(rand());
            QuickSort(ArrayQS.begin(), ArrayQS.size()); },
        [] { std::vector<double> ArrayS;
            for (int i = 0; i < 1e6; i++)
                ArrayS.push_back(rand());
            sort(ArrayS.begin(), ArrayS.end()); });

10 - Кол-во итераций для подсчетов (сколько раз будет вызываться каждая лямба функция)
[] { std::vector<double> Array;
            for (int i = 0; i < 1e6; i++)
                Array.push_back(rand()); }    - это общая часть для всех лямбда функций, которая меня не интересует.
Среднее время выполнения этого блока будет вычитываться из среднего времени выполнения всех остальных блоков.
Остальные параметры - такие же как и в SpeedTest().
